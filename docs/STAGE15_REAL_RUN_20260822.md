## 范围与运行方式

复用 `rerun_qwen35omni_stage1` 的 10 份 qwen3.5-omni-plus 字幕，不重跑 Stage 1。字幕审核、候选帧验收和源图关系判断通过用户授权的 HTTPS Anthropic 中转站使用 `claude-sonnet-5`。全部结果写入独立目录，没有覆盖旧结果。

运行中发现并修复三类 Anthropic relay 结构兼容：枚举值被包装为 `type/primary/category/relationship` 对象、枚举概率表、过程时间使用 `start_s/start_sec/start_time` 与对应 end 别名。协议适配只展开包装，不改变模型语义判断。

## 基线结果

升级版 Stage 1.5 初始真实运行仅保留 6 个单题视频，均选出 1 张但全部 `needs_review`；`BV1fKMQzUEQx`、`BV1JFp7zdEzH`、`BV1RC2XBdEnq`、`BV1ze2JY5EMV` 被整体 reject。模型的共同理由是“教程已经揭晓答案”或“航拍只是调查素材”，与本项目从完整讲解视频蒸馏监督链的目标冲突。

审核提示修正为：把时间截在每道题原图首次出示处；后续答案揭晓、AI 对战、人工复盘不能成为 reject 理由；航拍/行车/步行现场是有效 `video_derived` 输入；题面时间、IP、活动范围和文字提示可以作为已知线索。

## 人工图像核验

程序给出的两个 accepted 均为假阳性：

- `BV1ze2JY5EMV__t01`：选中带视频字幕和包装边缘的局部树干帧，缺少电塔/山坡的完整定位上下文；
- `BV1fKMQzUEQx__t02`：选中社交平台截图内嵌的小尺寸待定位图，带账号信息和视频字幕，并非干净题面原图。

因此名义 accepted 为 2/22，人工确认可直接入高质量 SFT 的 accepted 实际为 0/22。当前 Stage 1.5 已能较完整地“发现 task 并产出候选图”，但还不能可靠地“选择干净、完整、真正作为题面输入的图片”。

## 其他工程问题

- 三视频并发明显加快跨视频处理，但中转站出现数次 524/连接失败；单帧失败会保留记录并继续其他候选；
- 同视频多个 task 当前仍顺序运行，长视频内部不能利用外层视频并发；
- relay 偶发把整个 JSON 放入畸形键中，个别帧仍可能验收失败；
- 多段 show_source 只选一张的规则对“同一照片反复展示”仍有误报；
- `BV1JF` 的 task 时间窗存在重叠，结构异常检查没有可靠触发复核。

## 结论

升级后的 Stage 1.5 在切题方面经过提示修正后明显改善：10 个视频全部保留，共识别 22 个 task；但最终选图质量仍是主要瓶颈。下一步应优先修复干净原图判定、内嵌小图裁切/再截图、同图重复展示误报和 task 时间窗重叠，而不是放宽 accepted 门槛。
