# Stage 2：有限次数的 Observation 纠错

Stage 2 默认启用 `STAGE2_OBSERVATION_REVIEW=true`。先生成一条结构有效的自由轨迹，然后用一次批量模型调用检查所有 `tool_call` 的 Observation；不重复运行 Stage 3 或完整 Stage 4。没有工具事件时不调用审核模型。

审核输出 `supported / fabricated / uncertain`。只有明确伪造且审核置信度不低于 0.85 才触发重新生成；选图错配、证据不全、参数缺失和低置信怀疑不触发事实性打回。审核材料包含本题字幕及最多一个前后相邻段，帮助确认先前已说明的地图操作；相邻题答案不得冒用成本题证据。

下一轮在原生成提示末尾加入括号提醒，例如：

> （上一轮 Observation 纠错提醒，仅用于本轮生成：上一轮第3步补写了材料没有的距离；保留有依据的地标匹配，删除无来源数值，不要再把计划或推断包装成工具返回。）

警示只进入内部生成 prompt，不是训练轨迹中的 Thought、参数、Observation 或 notes。它说明上一轮的具体问题，而不是要求模型无条件接受审核结论或创造新事实。

`STAGE2_MAX_GENERATIONS=3` 表示 **首次生成 + 最多两次重新生成**，硬上限为三次，不是首次后再重试三次。渠道措辞修正和结构错误重试也占用同一 Stage 2 生成预算；单轮 `call_structured(max_attempts=1)` 避免适配器层再嵌套业务重试。工作范围抽取、审核调用和协议级流式回退不是新一轮轨迹生成。正常轨迹花费一次生成和一次批量审核；最坏是三轮生成及三轮审核，不逐步调用裁判。

第三轮仍有问题时保存最后一条结构有效的轨迹，记录 `continued_with_issues=true` 并继续 Stage 3/4。审核服务失败不会被当成通过，也不会删除已生成轨迹；重新生成失败时保留最近一次有效版本。若三次都没有得到任何结构有效轨迹，则仍报告生成错误，不能凭空造一条轨迹继续。

每题额外输出 `stage2_observation_audit.json`，保留实际生成次数、各轮轨迹、各轮问题、选中版本和实际入模图片清单。Stage 4 读取最终轮审核，不混用第一轮的问题；Observation 内容改变后通过摘要校验识别旧审核失效。`reject` 仍只是 Stage 4 的质量建议，不阻止文件保存。循环不是“保证零虚假”的承诺，未修复/未确认内容继续交人工审核。

本模块沿用项目已配置的 LLM 适配器与 API 授权，不执行真实地图、OSM 或检索工具，也不新增服务地址。单元测试默认 `ALLOW_REAL_API=false`，以可注入的审核回调覆盖通过、纠错成功、三轮仍错、审核失败及后续阶段继续执行等边界。
